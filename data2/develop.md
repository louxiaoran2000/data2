# 三、错误类型与问题编号

**每条记录内从 P01、P02 依次编号，下一条重新从 P01 开始。**E01—E08 表示错误类型，例如 `P01｜E04`。同一事实只记一个问题点；允许多个类型，但须逐类说明判断理由，不重复计数。

|**类型代码**|**问题类型**|**标注边界**|
|---|---|---|
|E01|明确指令未遵循|违反指令已写明的范围、限制或禁止事项。明确约束被违反时优先使用本类。|
|E02|需求理解偏差|理解错误、遗漏功能、边界未实现、未完成，或只修表面而未达到要求。代码质量好不能抵消漏需求；已说明假设且合理处理歧义不标。|
|E03|幻觉或失实陈述|编造不存在的 API、库、参数或事实；虚构完成状态，工具失败仍声称成功，或无依据地断言根因。已被工具当场纠正且最终结论改正的不标 E03；实际失败调用可按 E04 记录并注明恢复。|
|E04|工具使用错误|工具、库、参数、路径、依赖或命令使用错误，以当前工具列表、OS、实际 Shell 和返回为准。安装失败先辨原因：错误命令或依赖选择记本类，环境本身不可用记 ENV。可行但明显绕远记 E06。|
|E05|代码质量问题|有证据的功能、兼容、安全或维护缺陷，如缺必要校验或错误处理、硬编码密钥、注入风险、结构混乱到难以继续修改。命名或拆分风格不同但清楚可维护的不标。|
|E06|效率与冗余|重复遍历或实现；状态未变时以相同参数重复调用；有明显更直接的现成工具却绕远；简单任务过度设计、过度推理；长期探查不开始工作。合理探索、必要校验、调整后的重试及仅“可以更快”不标。分析重复仅依据轨迹中可见内容。|
|E07|沟通与解释问题|错误解释根因、前后矛盾、灌水、答非所问，或遗漏必须说明的状态与限制。修复正确但根因解释错误仍须标注；必要运行说明不标。“分析语言不统一”仅依据可见分析且存在理解影响或明确语言约束，不因中英混用直接标错。|
|E08|偏离任务或越权操作|分心修复非主线问题、非必要重构、擅加功能、未授权删文件，或在明确禁止时构建、测试或启动服务。违反写明的约束优先 E01；必要连带修改及默认允许的自测不标。|

非模型原因造成的环境故障记 `ENV`；用户误操作、主动转向或题目问题记 `USER`。这两类及无法确定的疑点填“异常与疑点”，不记为已确认的 Agent 错误。Windows 存在可用 Bash、WSL 时，Unix 命令本身不构成错误。“知识不足”须写明缺哪类知识及判断理由，不能代替幻觉或漏读需求；能归类时使用已有类型，确实无法归类才记“其他”。

# 四、每个错误点怎么标

在本条记录的**“问题标注”**中逐点填写以下内容；评阅时结合原始会话核查。

|**标注项**|**填写内容**|
|---|---|
|编号与类型|P01、P02…及错误类型；多个类型分别说明理由。|
|问题现象|Agent 做错、遗漏或多做了什么。|
|判断理由|为什么属于该类错误，避免只写“不合理”“效果不好”。|
|影响与恢复|造成什么影响，是否已纠正。已确认错误保留记录，恢复后不夸大影响；E03 按其自纠正规则判定。|
|改进建议|本应如何处理，或还需要检查什么。没有依据时不确定根因。|

**示例，仅说明写法：**

P01｜E04 工具使用错误。现象：运行测试时使用了当前工具不支持的参数，命令失败。判断理由：参数用法错误，不属于环境故障。影响与恢复：增加一次失败调用，更正参数后测试通过，已恢复。改进建议：使用当前版本支持的参数。

未发现错误时选择“未发现错误”，“问题标注”可留空；不能确定时选择“暂不能判断”，在“异常与疑点”说明原因。有已确认错误又有疑点时，选择“发现错误”，两类分别填写。风格偏好、合理探索、未补充指令未要求且非必要的测试，一般不标。轨迹缺失须重采，不能用“暂不能判断”代替。

# 六、CLI 轨迹提取

作答前确认 CLI 保存会话文件。全部阶段、回复和子任务结束后正常退出 CLI，再按下列步骤复制本次轨迹。

|**CLI**|**Windows 默认目录**|**macOS / Linux 默认目录**|
|---|---|---|
|Claude Code CLI|`%USERPROFILE%\.claude\projects\`|`~/.claude/projects/`|
|Codex CLI|`%USERPROFILE%\.codex\sessions\`|`~/.codex/sessions/`|

Windows：将目录粘贴到文件资源管理器地址栏；macOS：在 Finder 按 `Command + Shift + G` 后粘贴目录；Linux：在文件管理器或终端打开目录。CLI 若运行在 WSL、容器或远程主机，应从实际运行环境中提取。

## Claude Code CLI

1. 进入本次项目对应的子目录，按作答时间找到 `<session-id>.jsonl`。目录名通常由项目路径转换而来，文件名是会话 ID。

2. 打开文件确认属于本题，并覆盖全部阶段及追加追问，然后复制原文件。若设置过 `CLAUDE_CONFIG_DIR`，从该目录的 `projects/` 下查找。`/export` 生成的是可读文本，本题使用原始 JSONL。[官方会话说明](https://code.claude.com/docs/en/sessions#where-transcripts-are-stored)

3. 若同目录中存在以该会话 ID 命名的文件夹，将其中的 `subagents/`、`tool-results/` 与主 JSONL 一起压缩为 ZIP，保留相对目录结构。这些分别保存子 Agent 轨迹和较大的工具输出。[官方文件目录说明](https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically)

## Codex CLI

4. 在 `sessions/` 下按年、月、日进入子目录，找到本次会话的 `rollout-*.jsonl`。结合项目目录、作答时间和会话内容确认文件，复制原文件。

5. 若设置过 `CODEX_HOME`，从该目录的 `sessions/` 下查找；已归档会话在同级的 `archived_sessions/` 下。[官方日志位置说明](https://learn.chatgpt.com/docs/reference/troubleshooting#feedback-and-logs)

6. 确认文件覆盖全部阶段及追加追问。若使用子 Agent，将属于本题的子会话 JSONL 一并打包。`codex exec` 默认重定向到文件的内容是最终回复，本题仍提取会话原文件；作答时不要使用关闭会话落盘的 `--ephemeral`。[官方非交互模式说明](https://learn.chatgpt.com/docs/non-interactive-mode#basic-usage)

**上传位置：**在交付表首条记录的“原始会话”上传 JSONL 或 ZIP。只收集本题会话及其附属轨迹文件，按第五节要求处理必要脱敏，保留原始格式和事件顺序。
